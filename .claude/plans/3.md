## Lo que entiendo que buscás

## Bounded context

No es un bounded context de negocio. Es infraestructura transversal de desarrollo: la base que van a usar todos los módulos (ADR-0002, ADR-0003) y el SMTP local para Notifications (D9 en Etapa 2). No crea schemas de módulos, no toca Identity, no define contratos y no implementa outbox (ADR-0005).

## Criterios de aceptación

- `docker compose up -d` levanta exactamente dos servicios: `postgres` y `mailpit`. Sin pgAdmin, sin app .NET, sin servicios extra.
- Postgres usa una imagen pinneada de PostgreSQL 17 con PostGIS y crea, en la base inicial, las extensiones `postgis`, `unaccent`, `pg_trgm` y `citext` (las cuatro que declara `docs/DATABASE.md`).
- Postgres responde `pg_isready`; Mailpit responde su health check propio. `docker compose ps` muestra ambos `healthy`.
- Los datos sobreviven a `docker compose down` y `docker compose up -d` (sin `-v`) y a reinicios de contenedor.
- Mailpit recibe correo por SMTP y lo muestra en la UI; los mensajes persisten en el volumen.
- Puertos y credenciales salen de `.env`; `.env.example` está versionado y `.env` queda ignorado por git.
- No hay secretos reales en el repositorio.
- README documenta: levantar, puertos, credenciales de desarrollo, verificación de extensiones, envío de prueba a Mailpit, reseteo destructivo y connection string de ejemplo para .NET.
- Sin migraciones, sin schemas de módulos, sin cambios en `appsettings*.json`.
- Imágenes y herramientas OSS, sin dependencias pagas.

## Diseño de la infraestructura

### `docker-compose.yml`

Sin clave `version` (Compose v2+). Sin `container_name` explícito: los nombres los deriva el proyecto de Compose (`platform-postgres-1`, `platform-mailpit-1`). Para correr dos worktrees en paralelo se usa `docker compose -p platform-<sufijo>`.

Servicio `postgres`:

| Clave | Valor |
|---|---|
| `image` | `postgis/postgis:17-3.7` |
| `environment.POSTGRES_DB` | `${POSTGRES_DB:-platform}` |
| `environment.POSTGRES_USER` | `${POSTGRES_USER:-platform}` |
| `environment.POSTGRES_PASSWORD` | `${POSTGRES_PASSWORD:?POSTGRES_PASSWORD is required in .env}` |
| `environment.TZ` | `UTC` |
| `command` | `["postgres", "-c", "timezone=UTC"]` |
| `ports` | `127.0.0.1:${POSTGRES_PORT:-5432}:5432` |
| `volumes` | `postgres-data:/var/lib/postgresql/data` y `./infrastructure/docker/postgres/init/20-extensions.sql:/docker-entrypoint-initdb.d/20-extensions.sql:ro` |
| `healthcheck` | `pg_isready -h 127.0.0.1 -U $${POSTGRES_USER} -d $${POSTGRES_DB}`, `interval: 5s`, `timeout: 5s`, `retries: 10`, `start_period: 20s` |
| `networks` | `platform` |

Detalle importante: se monta **el archivo**, no la carpeta, sobre `/docker-entrypoint-initdb.d`. Montar la carpeta oculta el `10_postgis.sh` que trae la imagen y que crea `template_postgis` y `postgis_topology`. El script propio corre después como `20-extensions.sql`.

Servicio `mailpit`:

| Clave | Valor |
|---|---|
| `image` | `axllent/mailpit:v1.34.0` |
| `environment.MP_DATABASE` | `/data/mailpit.db` |
| `environment.MP_MAX_MESSAGES` | `5000` |
| `environment.MP_SMTP_AUTH_ACCEPT_ANY` | `1` |
| `environment.MP_SMTP_AUTH_ALLOW_INSECURE` | `1` |
| `environment.TZ` | `UTC` |
| `ports` | `127.0.0.1:${MAILPIT_SMTP_PORT:-1025}:1025` y `127.0.0.1:${MAILPIT_UI_PORT:-8025}:8025` |
| `volumes` | `mailpit-data:/data` |
| `healthcheck` | No se declara en compose: la imagen ya trae `HEALTHCHECK CMD ["/mailpit", "readyz"]`. Se verifica con `docker compose ps` / `docker inspect`. |
| `networks` | `platform` |

Volúmenes y red:

- `postgres-data`, `mailpit-data`: volúmenes nombrados, sin `name` fijo, para que Compose los prefije con el proyecto.
- `platform`: red bridge sin subred fija. Los servicios se resuelven por nombre (`postgres:5432`, `mailpit:1025`).
- Puertos publicados solo en loopback (`127.0.0.1`): no se expone la BD ni el SMTP a la LAN.

### `infrastructure/docker/postgres/init/20-extensions.sql`

Contenido conceptual, idempotente:

- `CREATE EXTENSION IF NOT EXISTS postgis;`
- `CREATE EXTENSION IF NOT EXISTS unaccent;`
- `CREATE EXTENSION IF NOT EXISTS pg_trgm;`
- `CREATE EXTENSION IF NOT EXISTS citext;`

Se ejecuta solo cuando el volumen de datos está vacío. Si se agrega o cambia una extensión después, hay que recrear el volumen (`docker compose down -v`) o aplicarla a mano en desarrollo. No se crean schemas de módulos: los crea cada migración de #4 en adelante.

### `.env.example`

Variables:

- `POSTGRES_DB=platform`
- `POSTGRES_USER=platform`
- `POSTGRES_PASSWORD=change-me-local`
- `POSTGRES_PORT=5432`
- `MAILPIT_SMTP_PORT=1025`
- `MAILPIT_UI_PORT=8025`

Incluye un ejemplo **comentado** de connection string para .NET:

`ConnectionStrings__Default=Host=localhost;Port=5432;Database=platform;Username=platform;Password=change-me-local`

Aclaración en el archivo y en README: `.env` lo lee Compose, no `dotnet run`. Para .NET hay que exportar la variable en la shell o usar user-secrets; la clave definitiva la fija #4.

### Integración con .NET

- Connection string de ejemplo (Npgsql): `Host=localhost;Port=5432;Database=platform;Username=platform;Password=change-me-local`.
- SMTP de ejemplo: `Host=localhost;Port=1025`, sin TLS. Mailpit acepta cualquier credencial en desarrollo.
- No se modifica `appsettings.json` ni `appsettings.Development.json`.
- No se agrega `Npgsql.EntityFrameworkCore.PostgreSQL` ni ningún paquete: eso es #4.

## Plan TDD / verificación

No hay test unitario para este issue. El “rojo” es que el stack local no existe; el “verde” es el smoke reproducible de abajo. Cada paso se marca en este archivo con la salida real.

1. **RED — confirmar que no hay stack local.**

   Se demuestra con: ambos comandos fallan (no hay `docker-compose.yml` y no hay Mailpit escuchando).
   - Hecho. `docker compose config -q` → `no configuration file provided: not found` (exit 1). `curl` → `Failed to connect to 127.0.0.1 port 8025` (exit 7). Puertos 5432/1025/8025 libres, sin volúmenes `platform_*`.

2. **GREEN — crear compose, `.env.example` y script de extensiones.**
   Crear los tres archivos con el diseño de arriba.
   Se demuestra con: `docker compose --env-file .env.example config -q` termina en 0.
   - Hecho. `config -q` exit 0. `.env` copiado desde `.env.example`; `git check-ignore -v .env` → `.gitignore:25:.env`.

3. **GREEN — levantar el stack y verificar health checks.**
   `cp .env.example .env` y `docker compose up -d`.
   Se demuestra con: `docker compose ps` muestra `postgres` y `mailpit` en `healthy`; `docker compose logs postgres` y `docker compose logs mailpit` no tienen errores.
   - Hecho. `platform-postgres-1` y `platform-mailpit-1` en `(healthy)`; `docker inspect` → `healthy` en ambos. Logs: solo warnings esperados de dev (`initdb: trust authentication for local connections`, Mailpit UI sin auth sobre loopback).

4. **GREEN — verificar Postgres, PostGIS y extensiones.**
   ```bash
   docker compose exec -T postgres psql -U platform -d platform -c "SELECT postgis_version();"
   docker compose exec -T postgres psql -U platform -d platform -c "SELECT extname FROM pg_extension WHERE extname IN ('citext','pg_trgm','postgis','unaccent') ORDER BY extname;"
   docker compose exec -T postgres psql -U platform -d platform -c "SELECT unaccent('ñandú'), similarity('electricista','electricisata'), 'a'::citext = 'A'::citext;"
   ```
   Se demuestra con: versión de PostGIS, cuatro filas de extensiones y resultados `nandu`, similitud > 0 y `true`.
   - Hecho. `postgis_version()` → `3.7 USE_GEOS=1 USE_PROJ=1 USE_STATS=1`; extensiones → `citext, pg_trgm, postgis, unaccent` (4 filas); `unaccent('ñandú')` → `nandu`, `similarity(...)` → `0.6875`, `citext` → `t`. `SHOW timezone` → `UTC`.

5. **GREEN — verificar Mailpit por SMTP y UI.**
   Enviar un correo con `python3` + `smtplib` a `127.0.0.1:1025`; consultar `http://127.0.0.1:8025/api/v1/messages` y abrir `http://127.0.0.1:8025`.
   Se demuestra con: `curl -fsS http://127.0.0.1:8025/readyz` responde 200 y el JSON de mensajes tiene `total >= 1`.
   - Hecho. Correo enviado por `smtplib`; `/readyz` 200; `/api/v1/messages` → `total=1`, asunto `Smoke test compose`; UI `http://127.0.0.1:8025/` → 200.

6. **GREEN — verificar persistencia.**
   Crear una tabla temporal `compose_smoke`, insertar una fila, `docker compose down`, `docker compose up -d` y consultar de nuevo. Repetir la consulta de mensajes de Mailpit.
   Se demuestra con: la fila y el correo siguen existiendo después del ciclo de contenedores. Luego `DROP TABLE compose_smoke`.
   - Hecho. Tras `down`/`up -d` (sin `-v`): fila `1 | persist` presente y `mailpit_total=1`. Reinicio de contenedor (`docker compose restart postgres`): tabla de prueba conservada. Ambas tablas de smoke eliminadas con `DROP TABLE`. `down -v` no se ejecutó: borra datos.

7. **REFACTOR / documentación.**

## Riesgos

| Riesgo | Impacto | Mitigación |
|---|---|---|
| Puertos 5432/1025/8025 ocupados | El stack no levanta | Puertos por `.env`; documentar cómo cambiarlos. |
| Volumen viejo de un intento anterior | Los scripts de init no corren y faltan extensiones | Detectar con `docker volume ls`; documentar `down -v` como destructivo y pedir confirmación antes de borrar. |
| Montar la carpeta de init sobre `/docker-entrypoint-initdb.d` | Se pierde el script de PostGIS de la imagen | Montar solo el archivo `20-extensions.sql`. |
| `postgis/postgis` oficial es solo `linux/amd64` | En Apple Silicon corre por emulación y lento | Dueño en Linux amd64; si aparece un dev arm64, decidir emulación o imagen alternativa no oficial. |
| Tags mutables | Una rebuild futura trae otra versión | Pin de tag `17-3.7` y `v1.34.0`; evaluar digest si hace falta reproducibilidad exacta. |
| `.env` con contraseña commiteado | Secreto en el repo | `.gitignore` ya lo cubre; `.env.example` solo con placeholder; revisar `git status` antes del commit. |
| Mailpit con auth accept-any | No debe usarse fuera de dev | Puertos en loopback y README marcado “solo desarrollo”; producción usa D9. |
| `pg_isready` pasa durante el servidor temporal de init | Un cliente podría conectar antes de las extensiones | Health check con `-h 127.0.0.1` para exigir el listener TCP final; verificación explícita de extensiones. |
| Connection string con `;` o caracteres especiales en la contraseña | Npgsql parsea mal | Placeholder simple en dev; documentar que la contraseña real no lleva separadores sin escapar. |
| Locale/collation por defecto no ideal para español | Ordenamientos con acentos | Fuera de alcance: la búsqueda usa `unaccent`/`pg_trgm`; revisar collation en #4 si aparece un caso real. |
| `.env` no lo lee `dotnet run` | El dev cree que la connection string está configurada y no lo está | README y `.env.example` lo dicen explícitamente; #4 define la config real. |
